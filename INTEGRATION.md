# Integrating the Browser Extension into your web2apk Repository

> This package was built standalone (the mobile-project files in the
> original upload were not rebuilt), so it ships as a self-contained set
> of additions. This guide shows exactly what to copy where, and how to
> keep versions in sync.

## What you're merging

```
web2apk/                      ← your existing repo (Android/iOS Capacitor template)
├── extension/                ← ADD — the whole folder
│   ├── manifest.json           MV3 manifest (Chrome & Edge)
│   ├── common.js               shared settings schema + helpers
│   ├── background.js           service worker
│   ├── icons/                  16/32/48/128 px PNGs
│   ├── popup/  options/  newtab/
├── scripts/
│   ├── generate-extension-icons.py   ← ADD (requires Pillow)
│   ├── validate-extension.mjs        ← ADD (requires Node ≥ 18)
│   └── build-extension.sh            ← ADD (requires zip)
├── .github/workflows/
│   └── build-extension.yml           ← ADD (new job, won't touch existing workflows)
├── EXTENSIONS.md             ← ADD (extension user/developer guide)
├── INTEGRATION.md            ← ADD (this file)
├── docs/
│   └── screenshot-newtab-1280x800.png ← ADD (store listing asset)
├── build/extension/          ← generated by build-extension.sh (gitignore)
└── dist/                     ← generated zips (gitignore)
```

Everything the extension needs lives under `extension/`, `scripts/`,
`.github/workflows/`, and the two markdown docs. Nothing in your
existing `www/`, `android/`, `ios/`, or Capacitor config is touched.

## Merge procedure

### 1. Copy the files

From the delivered `web2apk-browser-extensions.zip`, copy:

```bash
# from the unzipped package root (contains extension/, scripts/, …)
cp -R extension/           /path/to/your/repo/
cp    scripts/generate-extension-icons.py \
       scripts/validate-extension.mjs \
       scripts/build-extension.sh     /path/to/your/repo/scripts/
mkdir -p /path/to/your/repo/.github/workflows
cp    .github/workflows/build-extension.yml /path/to/your/repo/.github/workflows/
cp    EXTENSIONS.md INTEGRATION.md   /path/to/your/repo/
mkdir -p /path/to/your/repo/docs
cp    docs/screenshot-newtab-1280x800.png /path/to/your/repo/docs/
```

### 2. Update .gitignore

Append if not already present:

```gitignore
build/
dist/
```

### 3. Wire the docs

Add links to your README's navigation/feature list:

```markdown
**Also available:** [Chrome & Edge browser extension](EXTENSIONS.md) —
one-click app windows, new-tab dashboard, quick links, status badges.
```

### 4. Verify

```bash
cd /path/to/your/repo
node scripts/validate-extension.mjs   # 18 checks, 0 errors expected
bash scripts/build-extension.sh       # → dist/chrome-extension-v2.1.0.zip, dist/edge-extension-v2.1.0.zip
```

Then load `extension/` unpacked in Chrome/Edge (`chrome://extensions` →
Developer mode → Load unpacked) and click through: popup → Options →
new tab → keyboard shortcuts → context menu.

## Version sync policy

The extension is a **sibling product**, not a submodule of the mobile
template:

- Mobile apps: `package.json` + `android/app/build.gradle` versionName — keep versioning as you have it.
- Extension: `extension/manifest.json` → `version` (e.g. `2.1.0`).

Conventions:

1. **Independent lines.** The extension starts at `2.1.0` (matching the
   template's v2.0.0 generation) and then versions independently. Bump it
   whenever extension files change; don't force it to track mobile releases.
2. **Tag releases.** `git tag ext-v2.1.0` + push triggers the CI job,
   which attaches the store zips to a GitHub Release — the exact bits
   CI validated. (Plain `v*` tags also work; use `ext-v*` if your repo
   already tags mobile releases as `v*`.)
3. **When you change `common.js` defaults** (the shared schema), bump
   the extension's **minor** version so sync-storage users get the
   migration-safe defaults on next update.
4. **Keep `common.js` self-contained.** It's shared verbatim between the
   service worker (`importScripts`) and UI pages (`<script src>`). No
   ES-module syntax in it, ever — that breaks the service worker.

## CI interplay

`build-extension.yml` is additive: it runs only when files under
`extension/`, `scripts/validate-extension.mjs`, `scripts/build-extension.sh`,
or its own definition change (plus manual dispatch). Your existing
Android/iOS workflows are unaffected. If your repo's default branch is
neither `main` nor `master`, edit the `on.push.branches` list.

## Uninstall / rollback

The extension is pure client-side state — deleting the `extension/`
folder, workflow file, scripts, and docs removes it completely. Users'
stored settings remain in their browsers until they remove the extension
there (normal browser behavior on store update or manual removal).

## Compatibility notes

- Manifest V3, `minimum_chrome_version: 110` — Chrome, Edge, Brave,
  Opera, Vivaldi (any Chromium ≥ 110).
- Firefox would need MV2-style tweaks (different APIs for optional host
  permissions and app windows); intentionally out of scope.
- Safari requires a native-app wrapper and an Apple Developer account;
  out of scope.
